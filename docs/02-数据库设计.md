# 02 · 数据库设计

> **SQLite**（Node 内置 `node:sqlite`，零外部依赖），**生产/演示双库完全隔离**：生产 `data/xianyu_workbench.db`（`SQLITE_PATH`）、演示 `data/xianyu_workbench_demo.db`（`SQLITE_DEMO_PATH`），WAL 模式。当前模式存 `data/mode.json`（默认 production）。
> 表结构定义：`sql/schema.sql`（两库共用）；初始化数据：`sql/seed_core.sql`（生产最小集：管理员/系统设置/定时任务，**无任何演示数据**）与 `sql/seed_demo.sql`（演示库：各功能丰富演示数据）。库文件首次打开时自动幂等初始化（无表建表、用户为空按模式写入种子）。
> 迁移说明（v1.1）：自 MySQL 迁移而来——`ENUM` → `TEXT+CHECK`、`DATETIME` → `TEXT`（本地时间 `'YYYY-MM-DD HH:MM:SS'`，SQL 内统一 `datetime('now','localtime')`）、`DECIMAL` → `REAL`、`AUTO_INCREMENT` → `INTEGER PRIMARY KEY AUTOINCREMENT`、`ON UPDATE CURRENT_TIMESTAMP` → `AFTER UPDATE` 触发器、内联 `KEY` → 独立 `CREATE INDEX`；表清单与业务语义不变。

## 1. 设计决策

1. **不使用外键约束**，数据关系由服务层维护 —— 与上游项目约定一致（[GH] README「数据库与初始化」，见 docs/01 §F15）。删除账号等级联操作在服务层事务中处理。
2. **所有表显式主键 + 必要索引**，时间字段统一 `TEXT` 本地时间，由服务端写入本地时间。
3. **金额用 REAL**（服务层 round2 兜底精度，前端格式化显示）。
4. **业务日志与数据分离**：回复处理日志、发货日志、任务历史独立成表，支撑日志中心查询。
5. **系统设置键值表**，服务端内置定义校验（类型/范围/枚举），未知 key 拒绝写入。

## 3. 关键字段与状态机

### 订单状态机
```
pending_paid ──支付──▶ paid ──发货成功──▶ delivered ──▶ completed
   ▲                    │ ▲                    │
   └── 未付款订单（模拟环境直接创建 paid）        └── closed / refunding（预留，未模拟）
paid + 虚拟商品：delivery_status = pending ──扣卡密成功──▶ sent
                                └──库存不足/未开自动发货──▶ failed ──补发任务/手动发货──▶ sent
```

### 任务状态机
`never → running（抢占认领 last_status='running'）→ success | failed`；执行完成自动排 `next_run_at = NOW() + interval_seconds`；进程中断的 running 状态由调度器 10 分钟后自动恢复为 failed。

### 卡密状态机
`available →（事务内 FOR UPDATE 锁定）→ sold（记录订单号/买家/售出时间）`；available 可被人工 disable。
