### 2.3 [GH] 配置项提炼（节选，[GH] README「配置说明」）

- 基础设施：`MYSQL_HOST/PORT/USER/PASSWORD/DATABASE`、`REDIS_*`（连接池/超时/Keepalive/健康检查/启动重试）、`TZ=Asia/Shanghai`

## 4. 核心业务流程提炼（两源交叉）

### 4.1 消息自动化主流程（[GH] F02/F09/F10 + [AF] A01/A05）

```
买家消息进入（闲鱼 WebSocket [GH-F01] / 平台推送 [AF-A05]）
  → 会话归档（买家维度，关联商品）
  → 消息过滤（过滤词/黑名单 [GH-F10]）
  → 风控限流（频率限制 [GH rate_service] + 随机回复间隔 [AF-A05]）
  → 规则匹配（优先级：商品专属 > 账号专属 > 全局；未命中走默认回复 [GH-F02]）
  → 随机延迟模拟人工 [AF-A05]
  → 发送回复（文本/图片 [GH-F02]；AI 大模型可选 [GH-F03]）
  → 回复处理日志（命中规则/策略/决策原因 [GH auto_reply_log_service]）
  → 通知推送（新买家消息 [AF-A07]）
```

### 4.2 自动发货流程（[GH] F04 + [AF] A02/A06）

```
买家下单支付
  → 虚拟商品判定（卡密类）
  → 自动确认发货（必须与自动发货联动开启 [AF-A06]）
  → 卡密库存锁定/扣减（多数量需多张，不足→失败 [AF-A06 多数量开关，⚠️ 不足时行为未验证]）
  → 发送卡密内容给买家
  → 订单状态/发货结果记录（发送结果记录 [GH-F04]）
  → 失败 → 定时检查未发货订单自动补发 [AF-A06 / GH delivery_timeout_task]
  → 通知（新订单/发货失败 [AF-A07]）
  → 自动评价/补单 [AF-A02]
```

### 4.3 账号保活流程（[GH] F01）

```
定时 Cookie 刷新 / 登录续期（scheduler 任务）
  → Cookie 有效性检查
  → 即将过期 → 预警；已过期 → 账号置错并告警通知
```

### 4.4 商品发布与擦亮流程（[GH] F06 + [AF] A03）

```
商品模板（素材/地址库）
  → 单品/批量发布（{n} 序号复用模板）
  → 发布日志
  → 定时自动擦亮（提高曝光 [AF-A03]；自动重新上架 [GH auto_relist_task]）
```

### 4.5 使用场景（[AF] A12）

兼职副业夜间值守、卡密商家全自动发货、工作室多账号矩阵、代运营分组管理。本工作台的「模拟控制台」即围绕这些场景演示全链路。

## 7. 不确定项汇总（⚠️）

1. **[GH] 源码未逐行验证**：clone 被网络重置，仓库结论基于 README 全文 + GitHub API 文件树。文件路径证据可信度中高，但具体实现细节（参数、阈值）未验证。
2. **[GH-F03] AI 回复**：功能存在（`ai_reply_engine.py`、`ai_provider_service.py`），但支持的模型供应商列表、上下文窗口策略、计费方式未公开验证。本工作台**未实现 AI 回复**，仅实现关键词/默认回复。
3. **[GH-F01] 私有协议**：与闲鱼服务器的 WebSocket 协议、消息签名、Cookie 鉴权（`token_manager.py`、`xianyu_async.py`）属平台私有协议，本工作台**不实现、不逆向**，仅预留 LiveConnector 扩展点（调用返回 50101）。
4. **[AF-A05] 风控策略**：「随机回复间隔、模拟真实用户行为模式」为产品宣传口径，具体策略不可验证。本工作台实现了随机延迟 + 频率限制两个可验证的最小机制。
5. **[AF-A06] 多数量发货开关**：数量 > 可用卡密时的行为（整单失败/部分发货）未公开。本工作台按「整单失败、可补发」实现。
6. **[AF-A02] 自动评价触发条件**：上游未说明（签收后？发货后？）。本工作台按「发货后 N 分钟」可配置延迟实现。
7. **[AF] 图片关键词回复的匹配对象**：买家发送图片时无文本可匹配。本工作台约定：图片消息命中任意启用的「图片关键词」规则即回复（关键词字段仅作备注）。为本地约定，非上游验证结论。
8. **[AF] 套餐文案矛盾**：「最多 10 个账号」与「Pro 3/5 账号」表述不一致，不影响本工作台（单机自托管无账号数限制）。
9. **本工作台会话为内存态**：进程重启后需重新登录（与 [GH] JWT 数据库托管不同），为单进程工作台的简化取舍，已在接口文档标注。
