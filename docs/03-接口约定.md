# 03 · 服务端接口约定

> 基地址：`http://127.0.0.1:8080`（`PORT` 可配置）。除 `/health` 与静态资源外均为 JSON API，前缀 `/api/v1`。

## 1. 统一响应格式（对齐上游约定 [GH-F15]）

```json
{ "success": true, "code": 200, "message": "操作成功", "data": { } }
```

**业务错误同样返回 HTTP 200**，以 `success=false` + 业务码区分（与上游一致）：

| code | 含义 |
| --- | --- |
| 200 | 成功 |
| 40001 | 参数错误 / 校验失败 / 不支持的请求方法 |
| 40002 | 资源不存在 |
| 40003 | 业务校验失败（如非虚拟商品不可发货） |
| 40004 | 状态冲突（如重复发货、已评价） |
| 40101 | 未登录 / 令牌无效 / 已过期 |
| 40301 | 需要管理员权限（预留） |
| 50001 | 服务器内部错误 |
| 50101 | 预留扩展点未实现（live 连接器） |

## 2. 鉴权

- `POST /api/v1/auth/login` 公开；成功返回 `{ token, user }`。
- 其余接口需请求头 `Authorization: Bearer <token>`。
- 会话为**内存态、滑动续期**（有效期 `SESSION_TTL_HOURS`，默认 24h）；服务重启后需重新登录。⚠️ 与上游 JWT-数据库托管不同，为单进程工作台的简化。

## 3. 分页约定

`?page=1&page_size=20`（page_size ≤ 200），返回：

```json
{ "list": [...], "total": 123, "page": 1, "page_size": 20 }
```

### 全局账号切换（工作台侧栏「当前账号」）
- 前端机制：侧栏顶部下拉切换器，选中账号持久化于 `localStorage(wb_active_account)`；系统设置 `default_account_id`（系统设置页可改，账号管理页每行「设为默认」按钮直达）作为登录/无选择时的默认回填，列表项带 ⭐ 标记。
- 后端过滤：以下列表接口支持 `?account_id=`（切换器自动附加）：
  - `/api/v1/items`（该账号商品）
  - `/api/v1/orders`（该账号订单）、`/api/v1/crm/buyers`（该账号买家档案）
  - `/api/v1/conversations`（该账号会话）
  - `/api/v1/logs/reply`、`/api/v1/logs/risk`（该账号日志）
  - `/api/v1/worry-free`（该账号无忧卖）
  - `/api/v1/reply-rules`（**作用于该账号**的规则 = 全局 + 账号专属 + 该账号商品的专属规则）
  - `/api/v1/card-products`（该账号商品绑定的卡券产品）
  - `/api/v1/tasks`（绑定该账号的任务 + 作用于全部账号的全局任务）
- 账号列表（`/api/v1/accounts`）自身即全量展示，不参与过滤；驾驶舱/利润/流量/市场等聚合分析页保持全账号口径。
- 默认账号相关设置：`PUT /api/v1/settings {default_account_id: "0"|账号ID}`（**管理员**），0=全部账号。

### WS 消息监听与真实发送（真实账号上线后自动运行，core/xianyuLive.js）
- 连接 `wss://wss-goofish.dingtalk.com/`（Cookie 鉴权）→ `/reg` 注册（accessToken + 设备号）→ 15s 心跳保活 → 令牌每小时自动刷新（刷新后重连）
- **买家对话自动入库**：推送解析后按买家去重写入 `xy_conversations`/`xy_messages`（未读计数联动），消息会话页与未读角标实时可见；推送中的闲鱼会话 ID 存入 `xy_conversations.session_id`
- **订单事件自动同步**：推送中的 `updateKey/bizOrderId` 解析为订单状态（待付款/已付款/已发货/交易成功/已退款/交易关闭 全状态映射），按订单号 upsert `xy_orders`
- **真实消息发送**（协议与参考实现一致 `/r/MessageSend/sendByReceiverScope`，等待平台回执确认）：
  - `xianyuLive.sendText(accountId, {sessionId, buyerId, text})`：文本消息（`xy_conversations.session_id` 作为 cid，需有真实推送记录的会话）
  - `xianyuLive.sendImage(accountId, {sessionId, buyerId, imageUrl, width?, height?})`：图片消息（URL 需闲鱼 CDN 或公网可访问）
  - 手动发送 `POST /api/v1/conversations/:id/send`：账号 WS 在线时**强制真实发送**（失败抛 40003 并落「发送失败」消息留痕）；WS 未在线时生产模式拒绝模拟发送，演示模式走模拟入库
  - 自动回复 `replyEngine.sendReply`：账号 WS 在线时真实发送，成功才写回复日志与命中计数
- 断线自动重连（指数退避）；未覆盖的事件类型保留原始数据日志供后续适配

## 5. Connector 扩展点（50101 边界）

`src/core/connector.js` 定义统一接口：`submitBuyerMessage / submitOrder / refreshCookie / publishItem / polishItem / fetchNewOrders / checkCookie`。

- `connector_mode=simulated`（默认）：SimulatedConnector，由模拟控制台驱动全链路。
- `connector_mode=live`：LiveConnector 所有方法返回 **50101**。与闲鱼真实对接（WebSocket/签名/Cookie 鉴权）属平台私有协议，本项目不实现；如需扩展请实现 LiveConnector 并自担合规风险（见 docs/01 §7.3）。

**扫码登录的边界说明**：`services/qrlogin.js` 实现的是「登录凭证获取」——调用闲鱼 passport/h5 登录端点生成二维码、轮询扫码状态并捕获 Cookie（参照 xianyu-super-butler 的 `qr_login.py` 移植），属于上述「自行扩展」声明的落地之一。业务连接器（消息同步、自动回复、发货等真实链路）仍维持 simulated/50101 边界不变。保存的 Cookie 为登录确认时上游返回的凭证 + 一次 h5 接口校验补全，明文存 `xy_accounts.cookie`（本机自用工具，请勿外泄）；未做完整 Cookie 的浏览器级补全（如需可参考上游项目的 Playwright 方案）。

## 6. 异常处理约定

1. 路由处理函数抛 `ApiError` → 统一包装为 `{success:false, code, message}`；未知异常 → 50001 + 服务端 error 日志（控制台/文件/数据库三路）。
2. 未捕获异常 / Promise 拒绝 → 全局处理器记录日志，服务不退出（单进程工作台取舍；uncaughtException 后状态可能不一致，建议重启）。
3. 异步自动回复失败 → 落 `xy_reply_logs`（process_status=failed, decision_reason=send_failed），不影响主请求。
4. 发货事务失败（卡密不足）→ 订单置 failed + 发货日志 + 通知 `delivery_failed`，可由补发任务或手动发货重试。
5. 任务执行异常 → task_runs 置 failed、任务 last_error 记录、通知 `task_failed`，10 分钟僵尸自动恢复。
6. 优雅停机：SIGINT/SIGTERM → 停调度器 → 关 HTTP → 关连接池。
